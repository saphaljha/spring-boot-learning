# Java Generics

A deep dive into generic programming in Java (`java.lang.reflect` and compiler mechanics), covering bounded type parameters, wildcard bounds (`PECS`), type erasure, and repository design patterns.

---

## 1. Why Generics? Type Safety & Compile-Time Checks

Prior to Java 5, collections operated on raw `Object` references, requiring manual casting and risking `ClassCastException` failures at runtime. Generics enforce type contracts at compile time.

```java
package com.roadmap.generics;

import java.util.ArrayList;
import java.util.List;

public class GenericsBasicsDemo {

    public static void main(String[] args) {
        // Without generics (legacy): runtime failure
        List rawList = new ArrayList();
        rawList.add("SKU-100");
        rawList.add(100); // Compiles fine, but causes runtime error downstream
        // String sku = (String) rawList.get(1); // Throws ClassCastException!

        // With generics: compile-time safety guaranteed
        List<String> parameterizedList = new ArrayList<>();
        parameterizedList.add("SKU-100");
        // parameterizedList.add(100); // Compile error: incompatible types
        String safeSku = parameterizedList.get(0); // No explicit cast needed
    }
}
```

## 2. Generic Classes, Interfaces, and Methods

Generics allow classes, interfaces, and methods to operate over parameterized types.

```java
package com.roadmap.generics;

// 1. Generic Class
public class ApiResponse<T> {
    private final boolean success;
    private final T data;
    private final String errorMessage;

    private ApiResponse(boolean success, T data, String errorMessage) {
        this.success = success;
        this.data = data;
        this.errorMessage = errorMessage;
    }

    // 2. Generic Static Factory Methods
    public static <T> ApiResponse<T> ok(T data) {
        return new ApiResponse<>(true, data, null);
    }

    public static <T> ApiResponse<T> error(String message) {
        return new ApiResponse<>(false, null, message);
    }

    public boolean isSuccess() { return success; }
    public T getData() { return data; }
    public String getErrorMessage() { return errorMessage; }
}
```

```java
package com.roadmap.generics;

// 3. Generic Interface (Standard Repository Base)
public interface Identifiable<ID> {
    ID getId();
}

public interface GenericRepository<T extends Identifiable<ID>, ID> {
    void save(T entity);
    T findById(ID id);
}
```

## 3. Bounded Type Parameters

Bounded type parameters restrict the types that can be substituted for a generic type argument.

* **Upper Bound (`<T extends SuperClass>`):** Restricts the generic type to a specific subclass or interface.
* **Multiple Bounds (`<T extends Number & Comparable<T>>`):** `T` must satisfy both constraints (classes first, followed by interfaces).

```java
package com.roadmap.generics;

import java.math.BigDecimal;

public class PriceCalculator {

    // Restricts T to numeric types that implement Comparable
    public static <T extends Number & Comparable<T>> boolean isDiscountValid(T discount, T maxAllowed) {
        return discount.compareTo(maxAllowed) <= 0;
    }

    public static void main(String[] args) {
        boolean valid = isDiscountValid(new BigDecimal("15.50"), new BigDecimal("20.00"));
        System.out.println("Is discount valid: " + valid);
    }
}
```

## 4. Wildcards and the PECS Principle

In Java generics, inheritance works differently than with standard types: `List<String>` is **not** a subtype of `List<Object>`. Wildcards (`?`) bridge this variance gap.

### The PECS Rule: **P**roducer **E**xtends, **C**onsumer **S**uper

* **Producer Extends (`? extends T`):** If you are reading data *from* a generic structure (it *produces* data for you), use `? extends T`. You **cannot** write to it (except `null`).
* **Consumer Super (`? super T`):** If you are writing data *to* a generic structure (it *consumes* data from you), use `? super T`. You cannot read typed data from it (reads come back as `Object`).

```java
package com.roadmap.generics;

import java.util.ArrayList;
import java.util.List;

public class PecsDemo {

    static class BaseProduct { }
    static class BookProduct extends BaseProduct { }
    static class EBookProduct extends BookProduct { }

    // PRODUCER: Reads products from the source list (Covariance)
    public static void processProducts(List<? extends BookProduct> producerList) {
        for (BookProduct product : producerList) {
            System.out.println("Processing product: " + product);
        }
        // producerList.add(new BookProduct()); // COMPILE ERROR: Producer is read-only
    }

    // CONSUMER: Adds products into the target list (Contravariance)
    public static void addBooks(List<? super BookProduct> consumerList) {
        consumerList.add(new BookProduct());   // Safe: BookProduct is-a BookProduct
        consumerList.add(new EBookProduct());  // Safe: EBookProduct is-a BookProduct
        // BookProduct item = consumerList.get(0); // COMPILE ERROR: Can only read as Object
    }

    public static void main(String[] args) {
        List<BookProduct> books = new ArrayList<>();
        addBooks(books);          // Consumes books
        processProducts(books);   // Produces books
    }
}
```

## 5. Type Erasure & Runtime Limitations

Java implements generics via **Type Erasure** to maintain backward compatibility with older Java versions:

* The compiler strips all generic type arguments (`<T>`) at compile time.
* Unbounded types (`<T>`) are replaced with `Object`.
* Bounded types (`<T extends Number>`) are replaced with their upper bound (`Number`).
* Synthetic bridge methods and type casts are inserted automatically.

### What Type Erasure Forbids

```java
package com.roadmap.generics;

public class ErasureRestrictions<T> {

    // 1. Cannot instantiate a generic type directly
    // T instance = new T(); // COMPILE ERROR

    // 2. Cannot create generic arrays directly
    // T[] array = new T[10]; // COMPILE ERROR

    // 3. Cannot use instanceof on parameterized types
    public void test(Object obj) {
        // if (obj instanceof List<String>) {} // COMPILE ERROR
        if (obj instanceof List<?>) {} // Allowed (Unbounded Wildcard)
    }

    // 4. Cannot use generic types in static context of the class
    // private static T staticField; // COMPILE ERROR
}
```

## 6. Key Takeaways for Magento / PHP Developers

1. **PHPDoc Annotations vs. Java Generics:** In PHP, generic annotations (`/** @var array<string, Order> */`) are purely advisory for static analysis tools (PHPStan / Psalm). In Java, generics are enforced by the compiler before any code is allowed to run.
2. **Spring Framework Foundation:** Spring Data JPA's core contracts (`JpaRepository<Entity, ID>`) directly depend on generics. Understanding bounds and wildcards is essential for writing custom repositories and API wrappers.
