# Modern LTS Features (Java 11 to 21)

A hands-on guide to modern Java enhancements (Java 11, 17, and 21 LTS) that simplify codebases, remove ceremony, and dramatically improve concurrency through Records, Pattern Matching, Sealed Types, and Virtual Threads.

---

## 1. Local-Variable Type Inference (`var`) (Java 10+)

The `var` keyword instructs the compiler to infer the variable type from the initialization expression on the right-hand side.

### Essential Rules
* Only works for **local variables** with initializers inside method bodies.
* Does not work for class fields, method parameter lists, or return types.
* Still produces a strictly typed variable (not dynamic typing like PHP or JavaScript).

```java
package com.roadmap.modernjava;

import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.net.URI;
import java.util.List;
import java.util.Map;

public class VarInferenceDemo {

    public static void main(String[] args) throws Exception {
        // Reduces verbose generic variable declarations
        var customerOrders = Map.of(
            "CUST-001", List.of("ORD-100", "ORD-101"),
            "CUST-002", List.of("ORD-200")
        );

        // Clean resource declaration
        var url = URI.create("https://api.github.com").toURL();
        try (var reader = new BufferedReader(new InputStreamReader(url.openStream()))) {
            var firstLine = reader.readLine();
            System.out.println("Payload read: " + firstLine);
        }
    }
}
```

## 2. Records: Immutable Data Carriers (Java 14/16+)

Records replace boilerplate POJOs (Plain Old Java Objects) and Lombok `@Value` annotations for Data Transfer Objects (DTOs), event payloads, and API requests/responses.

### What the Compiler Generates Automatically
* `private final` fields for all record components.
* Public accessor methods (e.g., `sku()`, `price()`—without the `get` prefix).
* Canonical constructor matching component parameters.
* Proper `equals()`, `hashCode()`, and descriptive `toString()` implementations.

```java
package com.roadmap.modernjava;

import java.math.BigDecimal;

// Compact, immutable DTO definition
public record ProductDto(
        Long id,
        String sku,
        BigDecimal price,
        boolean inStock
) {
    // 1. Compact Constructor for declarative validation
    public ProductDto {
        if (price == null || price.compareTo(BigDecimal.ZERO) < 0) {
            throw new IllegalArgumentException("Price cannot be null or negative");
        }
        sku = sku.trim().toUpperCase(); // Field normalization
    }

    // 2. Custom helper domain behavior
    public boolean isDiscountEligible() {
        return inStock && price.compareTo(new BigDecimal("100.00")) >= 0;
    }
}
```

## 3. Sealed Classes & Interfaces (Java 17+)

Sealed types allow a class or interface to explicitly restrict which subclasses or implementations are permitted to extend or implement it.

### Modifiers for Permitted Subclasses
* `final`: Cannot be extended any further.
* `sealed`: Can be extended, but only by its own specified permits list.
* `non-sealed`: Re-opens the hierarchy to unrestricted extension.

```java
package com.roadmap.modernjava;

// Sealed interface: only the 3 listed records can implement it
public sealed interface OrderPaymentEvent
    permits PaymentAuthorized, PaymentCaptured, PaymentFailed {

    String orderId();
}

record PaymentAuthorized(String orderId, double amount, String authCode) implements OrderPaymentEvent {}
record PaymentCaptured(String orderId, double amount, String captureRef) implements OrderPaymentEvent {}
record PaymentFailed(String orderId, String failureReason) implements OrderPaymentEvent {}
```

## 4. Pattern Matching (Java 16 & Java 21)

Pattern matching eliminates verbose explicit casts when checking instance types.

### A. Pattern Matching for `instanceof` (Java 16)

```java
package com.roadmap.modernjava;

public class InstanceOfPatternDemo {

    public static String formatPayment(Object payment) {
        // Modern pattern matching: condition check + cast in one step
        if (payment instanceof PaymentCaptured pc && pc.amount() > 500.0) {
            return "Large capture: " + pc.captureRef() + " for $" + pc.amount();
        } else if (payment instanceof PaymentFailed pf) {
            return "Alert: Payment failed due to " + pf.failureReason();
        }
        return "Generic Payment Type";
    }
}
```

### B. Pattern Matching for `switch` (Java 21)

When used alongside sealed types, `switch` expressions can achieve **compiler-verified exhaustiveness** (no fallback `default` case required).

```java
package com.roadmap.modernjava;

public class SwitchPatternMatchingDemo {

    public static String handleEvent(OrderPaymentEvent event) {
        // Compiler guarantees all permitted subtypes of OrderPaymentEvent are covered
        return switch (event) {
            case PaymentAuthorized pa -> "Hold stock for Auth: " + pa.authCode();
            case PaymentCaptured pc when pc.amount() > 1000.0 -> "Trigger fraud audit for high-value capture: " + pc.captureRef();
            case PaymentCaptured pc -> "Fulfill order: " + pc.orderId();
            case PaymentFailed pf -> "Cancel checkout workflow: " + pf.failureReason();
        };
    }
}
```

## 5. Text Blocks (Java 15+)

Text blocks preserve multiline formatting and avoid messy quote escaping when embedding JSON payloads, HTML templates, or native SQL queries.

```java
package com.roadmap.modernjava;

public class TextBlocksDemo {

    public static void main(String[] args) {
        // Raw JSON without escaping double quotes
        String sampleJson = """
                {
                    "orderId": "ORD-5541",
                    "status": "PROCESSING",
                    "currency": "EUR"
                }
                """;

        // Native SQL string representation
        String complexQuery = """
                SELECT o.id, o.order_number, SUM(i.quantity * i.unit_price) AS total
                FROM orders o
                JOIN line_items i ON o.id = i.order_id
                WHERE o.status = 'COMPLETED'
                GROUP BY o.id, o.order_number
                ORDER BY total DESC;
                """;

        System.out.println(sampleJson);
        System.out.println(complexQuery);
    }
}
```

## 6. Virtual Threads: Project Loom (Java 21 LTS)

Prior to Java 21, platform threads mapped directly 1:1 to heavy operating system threads (each consuming ~1MB of memory), capping server concurrency around a few thousand concurrent threads.

**Virtual Threads** are lightweight, JVM-managed threads (~few kilobytes) that decouple Java execution threads from OS threads. Millions of virtual threads can run concurrently on standard server hardware.

```
Application Layer
  [ Virtual Thread 1 ]   [ Virtual Thread 2 ] ... [ Virtual Thread 100,000 ]
           |                      |                          |
           +----------------------+--------------------------+
                                  v
JVM Scheduler (Mounts / Unmounts on I/O block)
  [ Carrier Thread 1 ]   [ Carrier Thread 2 ] (Pool of OS Kernel Threads)
           |                      |
           v                      v
      CPU Core 1             CPU Core 2
```

### Execution Example: Virtual Thread Executor

```java
package com.roadmap.modernjava;

import java.time.Duration;
import java.util.concurrent.Executors;
import java.util.stream.IntStream;

public class VirtualThreadsDemo {

    public static void main(String[] args) {
        long start = System.currentTimeMillis();

        // High-throughput virtual thread executor
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            IntStream.rangeClosed(1, 10_000).forEach(taskId -> {
                executor.submit(() -> {
                    // Blocking I/O unmounts the virtual thread from the carrier OS thread
                    Thread.sleep(Duration.ofMillis(100));
                    return taskId;
                });
            });
        } // Executor auto-closes and awaits all 10,000 virtual threads

        long duration = System.currentTimeMillis() - start;
        System.out.println("10,000 concurrent blocking tasks finished in: " + duration + "ms");
    }
}
```

## 7. Key Takeaways for Magento / PHP Developers

1. **DTO Boilerplate Elimination:** In PHP, class constructors with promoted properties (`public function __construct(public string $name)`) simplify transfer objects. In Java, **`record`** provides an even cleaner, immutable equivalent that automatically includes JSON serialization compatibility out of the box in Spring Boot.
2. **Virtual Threads vs. Asynchronous PHP:** PHP relies on external event loops (Swoole, ReactPHP) or Node.js-style async/await to handle high concurrency. Java 21 achieves massive throughput while keeping familiar, readable **blocking, synchronous code** via Virtual Threads.
